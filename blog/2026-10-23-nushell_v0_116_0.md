### Named flags: null can omit or pass through based on type <JumpToc/> <PrBy :pr="18796" user="fdncred" />

When a named flag is given `null`, Nushell now:

- **Omits** the flag if its type does not accept `nothing` (e.g. `--x: int`, `--preserve: list<string>`), so defaults and “flag not passed” behavior work—especially useful when shadowing builtins with `%cp` / `%ls` and writing `--flag=$maybe_null`
- **Passes `null` through** if the type accepts `nothing` (e.g. `--x: any`, `--x: oneof<int, nothing>`), so callers can still express an explicit null when they opt into that in the signature

```nushell
def f [--x: oneof<int, nothing> = 5] { $x }
f            # 5
f --x=null   # null

def g [--x: int = 5] { $x }
g --x=(null)   # 5 (omitted → default) note: in this example null is wrapped in parens because this syntax would fail with `g --x=null` as you're typing due to parse checking.
```

### Record spread into named flags

Internal and custom commands accept spreading a record as named flags:

```nushell
def wrap [--preserve: list<string>, --recursive, ...rest] {
  %cp ...{ preserve: $preserve, recursive: $recursive } ...$rest
}

let flags = {preserve: [mode], recursive: true}
wrap ...$flags src dest
```

- Null fields follow the same type rule as named flags above
- Switch fields: `true` sets the flag; `false` / `null` omit
- Field values are type-checked against the flag signature
- Unknown flag names in the record error at runtime
- Spreading a **list** into a command with no `...rest` errors clearly (it is not treated as named flags)

### Summary <JumpToc/> <PrBy :pr="19025" user="fdncred" />

This PR adds a `tui` command family so a Nushell user can build an interactive TUI or popup from a pipeline, without writing Rust. The commands live in a new `nu-tui` crate; the ratatui style conversions are shared with `explore`.

Interactive `tui run` always uses the alternate screen, so the shell comes back intact when you quit. `--dialog` is the same session in a smaller floating window. `tui debug` paints the same UI to a string and reports how it was laid out, for scripts and tests.

`tui run` returns one record, `{action, focused, selected, page, values, rows, live}`, where `values` holds every widget's state by id. Colors come from a new `$env.config.tui` section (documented in `config nu --doc`).

Also in this PR: `nu-utils` now reads the OS locale once per process. `sys_locale` goes through CoreFoundation on macOS and its autoreleased objects were never collected on a plain Rust thread, so any loop that formats filesizes (the TUI redraws per frame) grew memory without bound.

### Command reference

Every builder takes `--id` and `--focus` (start with that widget focused). Data widgets (table, tree, log, select, progress, label) also take `--data` and `--from`; list widgets (table, tree, select) also take `--on-select` and `--multi`. The remaining flags are listed.

### Layout model

Widgets in the outer pipeline stack top to bottom, one row each. The exception is buttons: adjacent `tui button`s pack onto one row, left to right (§12). `tui split`, `tui box`, and `tui tab` take a list of child widgets and arrange them. Children are built inside parentheses:

```nushell
ls
| tui label --title "files"
| tui split --sizes [60% 1fr] [
    (tui box "list" [ (tui search --bind /) (tui table --columns [name type size]) ])
    (tui preview { nu-highlight })
  ]
| tui label --status "enter: pick  /: filter  q: quit"
| tui run
```

Chrome, that is `tui label --title`, `tui label --status`, and `tui menu`, goes in the outer pipeline only and stays visible on every page. `tui tab` is also outer-pipeline only. `tui search` can go in either place; its position decides what it filters (§3).

Auto ids are `table-0`, `search-0`, …, numbering widgets of each kind in tree order. When two children both contain a `table-0`, the second becomes `table-1` and a `--from table-0` inside that child follows it. An explicit `--id` is never renumbered; two of the same explicit id is an error. Pass `--id` when another widget needs a stable name; `tui debug` shows the resolved ids.

### Data flow

Each widget shows the first of these that exists:

1. its own `--data`, or the value piped into it inside a child list (`[(ls | tui table)]`);
2. what its `--from` source produced (§4);
3. the nearest ancestor container's data;
4. the outer pipeline's data.

So one pipeline can feed every list, or each pane can have its own rows:

```nushell
ls | tui split [ (tui table) (tui tree) ] | tui run           # both read ls
tui split [ (ps | tui table) (ls | tui table) ] | tui run      # each has its own
tui split [ (tui table --data (ps)) (tui table --data (ls)) ]  # the same, spelled out
```

A builder reads a stream for a quarter of a second. A producer that finishes in that time (`ls`, `ps`, `open`) is collected into the widget's data; one that keeps going (`1..`, `tail -f`) stays live and flows on to `tui run` (§9). A child list can only hold collected values, so keep unbounded producers in the outer pipeline.

### Hook contract

One contract covers every closure that reacts to the user: `tui bind`, menu `action`s, `tui button`, `--on-select`, and the `tui run` closure. The hook receives the state record (the same record `tui run` returns, §Result record) as `$in`, and as its first parameter when it declares one. Its output decides what happens:

| Returns                           | Effect                                                            |
| --------------------------------- | ----------------------------------------------------------------- |
| nothing                           | nothing changes                                                   |
| `{action: submit, selected: ...}` | the TUI closes with that selection                                |
| `{action: quit}`                  | the TUI closes without a selection                                |
| anything else                     | it replaces the shared data list; every widget reading it redraws |

An error goes to the status bar as `error:…` and the TUI stays open.

```nushell
ls
| tui table
| tui bind ctrl+r {|| ls }                                              # reload
| tui bind s {|state| {action: submit, selected: $state.selected.name} } # submit the name
| tui run
```

## Performance <JumpToc/>

### Faster typing of `use` in the REPL <JumpToc/> <PrBy :pr="18841" user="fdncred" />

The REPL no longer parse-time-loads a module just to syntax-highlight it. Typing `use std` or `use std/iter` no longer stalls on the first exact match of `std` (most noticeable in debug builds). Execution is unchanged: the module still loads when you run the line.

Completing `use std/` (and `export use` / `overlay use`) lists virtual standard-library children without walking the current directory. `$NU_LIB_DIRS` is still searched. Completing a real path such as `use ./foo/` is unchanged.

Syntax highlighting also does less work per keystroke: it reuses the last parse of the same line (for example when only the cursor moves) and copies less text while painting.

```nushell
# These should feel instant to type in the REPL, including debug `cargo run`
use std
use std/iter
use std/assert
```

### `$nu.startup-time` is now accurate and Nushell starts faster with large configs <JumpToc/> <PrBy :pr="19049" user="fdncred" />

- `$nu.startup-time` now measures from process creation (on macOS and Windows; from `main` on other platforms) to the moment the first prompt is ready, so it includes config files, plugins, `env_change` and `pre_prompt` hooks, and prompt evaluation. Hooks that run before the first prompt see a provisional value; the final value is available from the first command on.
- The banner's "Startup Time" line is now printed right before the first prompt, after the startup hooks, so it shows the final value. The welcome message still appears first; output from `env_change`/`pre_prompt` hooks now lands between the welcome message and the startup time line. `banner` gained a `--no-startup-time` flag.
- `$nu.startup-time` is now set when running a script (it was `-1ns`).
- Improved performance of parsing config files and modules: command lookups no longer rebuild overlay visibility maps, which roughly halves config load time for configs that `use` many modules.
- Improved performance of loading the plugin registry file (about 5x on a 20-plugin registry).
- `gstat` computes the nearest tag much faster on large repositories (about 4x on the nushell repo); output is unchanged.
- `table` and `term size` no longer spawn `tput` when no terminal is attached; they use `COLUMNS`/`LINES`, or 80x24, instead.
- `--log-level perf` now reports the time spent before `main`, engine setup, standard library loading, and a final "startup (process start to first prompt)" line.

## Bug fixes <JumpToc/>

### `lines --skip-empty` now works consistently across input types <JumpToc/> <PrBy :pr="18872" user="fdncred" />

`lines --skip-empty` now skips empty lines for string and byte stream input, not only list streams.

```nushell
"foo\n\nbar" | lines --skip-empty
# ╭───┬─────╮
# │ 0 │ foo │
# │ 1 │ bar │
# ╰───┴─────╯
```

Whitespace-only lines are treated as empty, same as they already were for list streams.

### `format pattern` and `parse` now reject unclosed `{` patterns <JumpToc/> <PrBy :pr="18871" user="fdncred" />

`format pattern` already reported a delimiter error for a lone `}`. A pattern that ended with `{` succeeded and dropped the brace. `parse` simple patterns did the same.

Both commands now treat an unescaped `{` without a matching `}` as a delimiter error.

```nushell
{} | format pattern '{'
# Error: nu::shell::delimiter_error (there are unmatched curly braces)

"hello " | parse "hello {"
# Error: nu::shell::delimiter_error (Found opening `{` without an associated closing `}`)
```

Escaped braces (`{{` and `}}`) still insert a literal brace. A lone `}` in `parse` is still a literal character to match, not an error. `parse --regex` is unchanged.

### `into string` now preserves string typing for semver values <JumpToc/> <PrBy :pr="18901" user="fdncred" />

```nushell
let s = "1.0.0" | into semver | into string
$s | describe
# string

"/tmp" | path join ("1.115.0" | into semver | into string)
# /tmp/1.115.0
```

### `format date` no longer errors under Thai, Lao and similar locales <JumpToc/> <PrBy :pr="18918" user="aron-intframe" />

`format date` with `%x`, `%X` or `%c` failed with `nu::shell::type_mismatch, invalid format` under locales such as `th_TH` and `lo_LA`, which write the year with a modifier the date library does not implement. The default config runs `date now | format date '%x %X'`, so affected users saw it at every startup. These now render in the locale's own field order, without the era:

```nushell
# with LC_TIME=th_TH.UTF-8
date now | format date '%c'
# before: Error: nu::shell::type_mismatch, invalid format
# after:  ศ. 22 ต.ค. 21, 20:00:12
```

A modifier you type yourself no longer errors either: `%Ey` and `%Od` now render as `%y` and `%d` would.

### `format date %r` now works under the last two locales that still failed <JumpToc/> <PrBy :pr="18924" user="aron-intframe" />

#18918 fixed `format date` under locales whose formats use `%E`/`%O`, but `az_IR` and `fa_IR` still failed on `%r`, because they define no am/pm format and their plain time format carries the modifier again:

```nushell
# with LC_TIME=fa_IR.UTF-8
date now | format date %r
# before: Error: nu::shell::type_mismatch, invalid format
# after:  20:00:12
```

Every other locale, including `de_DE`, `fr_FR` and `nl_NL`, renders exactly as before.

### Faster repeated `source` of the same file <JumpToc/> <PrBy :pr="18948" user="fdncred" />

0.115 started re-parsing every `source` / `source-env` of a file that had already been parsed, so configs and libraries that `source` the same helpers many times got slower as more files were loaded. A 63-file case that stayed around 50ms in 0.114 grew to hundreds of milliseconds.

After this PR `source` / `source-env` go through `parse()` again. A cached block is reused only when it is safe. Stale captures fall through and parse fresh. That is the #18515 path. Empty-capture libraries hit the cache. That is the 0.114 path.

### Table display now respects `$env.config.table.trim` wrapping and truncating more consistently <JumpToc/> <PrBy :pr="18979" user="fdncred" />

Fixed `$env.config.table.trim` so wrapping and truncating actually differ on default table display (`table -e` on terminals 100 columns or wider), including with `header_on_separator`.

- **wrapping**: more columns; long cells wrap onto extra lines.
- **truncating**: one line per row; extra columns dropped with a trailing `...`; a squeezed cell gets `truncating_suffix`.
- Columns are no longer squeezed to a single character (the `size` / `s/i/z/e` ladder).
- The trailing `...` column is not `truncating_suffix`. That suffix only appears when a visible cell is cut.

Example:

#### wrapping

```nushell
~/src/nushell> $env.config.table.trim = { methodology: wrapping, truncating_suffix: "..." }
~/src/nushell> ls -al
╭────┬───────────────┬─────────┬───────────┬──────────┬───────────┬───────────┬───────────┬─────────┬───────┬──────────┬────────────┬─────╮
```

### `length`, `columns`, and `is-empty` now surface errors from streamed input <JumpToc/> <PrBy :pr="18976" user="sidsri14" />

Fixed an issue where `length`, `columns`, and `is-empty` / `is-not-empty` could silently ignore errors in streamed input and return incorrect results instead of surfacing the original error.

For example, `[[name size]; [a 100b] [b 200b]] | where size <= 150 | length` now errors with `nu::shell::operator_incompatible_types` instead of returning `2`, and likewise for `columns` / `is-empty`.

### Chained `par-each` pipelines no longer deadlock on same-size thread pools <JumpToc/> <PrBy :pr="18999" user="zozo123" />

Only reuse idle cached pools and retain a producer reference until completion to prevent deadlocks between chained streaming stages.

Adds a single-worker, 100-value regression test. Compilation and tests have not been run.

### Expanded nested tables now keep their table borders when cells wrap <JumpToc/> <PrBy :pr="19007" user="fdncred" />

Fixed `table --expand` wrapping nested tables as text, which broke their borders (for example `plugin list` after #18979).

Long cells in nested tables still wrap or truncate **inside** the inner table according to `$env.config.table.trim`. The inner box stays a table. Scalar columns on the parent still wrap or truncate the same way as in #18979.

### `mkdir --verbose` no longer reports existing directories as newly created <JumpToc/> <PrBy :pr="19017" user="Developer1010x" />

Fixed `mkdir --verbose` reporting `created: true` for directories that already
existed. Such rows now report `created: false`. Directories that are actually
created are unaffected.

### Fix(view source): put a space after the colon on a rest parameter <JumpToc/> <PrBy :pr="19024" user="Developer1010x" />

`view source` now renders a rest parameter as `...rest: string` rather than
`...rest:string`, matching how it already renders every other parameter.

### `finally` now always runs, in the right order, however a `try` block is left <JumpToc/> <PrBy :pr="19052" user="fdncred" />

- Fixed an issue where a `finally` block inside a nested `try` was skipped when an outer `try { } catch { }` caught the error (#19051). Every `finally` between the error and the `catch` that handles it now runs, innermost first.
- Fixed an issue where, after an error or `return` inside `try { } finally { }`, the statements following the `try` expression kept executing before the error or return took effect.
- Fixed `finally` being skipped when the error was raised inside a `catch` block or inside another `finally` block and then caught further out. An error raised in `finally` replaces the original error, as before.
- `break` and `continue` inside `try { } finally { }` now run the `finally` block on their way to the loop. Previously they skipped it, could pop an enclosing `catch` handler by mistake, and left a handler behind that fired on a later, unrelated error in the same block.
- `$in` inside a `finally` block is now always defined: the value produced by `try`/`catch` on success, the error record on the error path, and `nothing` for `return`, `exit`, `break` and `continue`. This matches the block's optional parameter (`finally {|x| ... }`).
- `view ir` shows new instructions for this: `begin-finally`, `end-finally` and `unwind-jump` replace `pop-finally`; the register-less `finally` instruction is gone.

### List literals and `match` patterns now reject semicolon separators <JumpToc/> <PrBy :pr="19063" user="windlandneko" />

List literals and `match` list patterns now reject unexpected semicolon separators instead of silently accepting malformed input or discarding subsequent content.

Header-only table syntax such as `[[a b];]` now also produces a parse error.

### LSP hover tooltips now render Markdown without accidental bold text <JumpToc/> <PrBy :pr="19080" user="fdncred" />

Fix the lsp hover tooltip markdown

### External completers now receive expanded alias commands and show warnings after menus close <JumpToc/> <PrBy :pr="19085" user="kronberger-droid" />

`$place.command` is the argv of the command the cursor is in, one shell word per argument, even after a pipe, inside a closure or after a `;`:

```nu
$env.config.completions.external.completer = {|place|
  carapace $place.command.0 nushell ...$place.command | from json
}
```

An alias head is expanded, so `gco ma` hands the completer `[git, checkout, ma]`.
The legacy `spans` input carries the same list, thus `foo [a b` is `[foo, "[a b"]`, no longer `[foo, "[", a, " ", b]`.
Menu `source` deprecation warnings show after the line is handed back instead of over the menu.
