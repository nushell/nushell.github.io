# Nushell 0.117.0

Today, we're releasing version 0.117.0 of Nu. This release brings structured output from external commands, a live REPL status line, easier completion generation, new record commands, dotenv support, and reusable type aliases.

# Where to get it

Nu 0.117.0 is available as [pre-built binaries](https://github.com/nushell/nushell/releases/tag/0.117.0) or from [crates.io](https://crates.io/crates/nu). If you have Rust installed you can install it using `cargo install nu`.

As part of this release, we also publish a set of optional [plugins](https://www.nushell.sh/book/plugins.html) you can install and use with Nushell.

# Highlights and themes of this release <JumpToc/>

## Less parsing, more piping <JumpToc/>

Your favorite command has perfectly good terminal output. Very readable, nice colors, absolutely not a table you can pipe into `where`. Thanks to [@fdncred](https://github.com/fdncred), the new `@structured` attribute lets you teach an external command how to provide structured data when you need it, without changing how it looks when you run it on its own.

```nushell
@structured [--porcelain] { lines | parse --regex '^(?<status>..) (?<file>.+)$' }
extern "git status" []

git status | where status =~ M | get file
```

Define it once, then get on with your pipelines. A plain `git status` still gives you Git's usual display, while piping it into a Nushell command adds the arguments and decodes the output for you. More details and examples are [here](#structured-data-from-external-commands).

## The REPL is one step ahead <JumpToc/>

Still typing? The REPL already has a few things to say. Thanks to [@fdncred](https://github.com/fdncred), a new status line beneath your input shows parse and type errors before you press Enter. When everything looks good, it shows the command signature with the current parameter emphasized, along with your pipeline's output type.

For expressions built entirely from const commands, it can even give you a preview of the result. Type `"a,b" | split row ","` and get a little `= [a, b]` sneak peek. Not quite doing your work for you, but getting suspiciously close. You can choose which parts appear with `$env.config.status_line`; take a look [here](#live-status-line-and-interruptible-math-reductions).

## Easy completions ahead <JumpToc/>

Writing out every flag your tools support is probably not how you wanted to spend the afternoon. The new `generate completions` command from [@fdncred](https://github.com/fdncred) can do some of that homework for you, generating Nushell extern definitions and completers from carapace specs, fish or zsh completions, man pages, or even `--help` text.

Save the generated module, load it, and let Tab take over a bit more of the typing. Depending on the source, that can include subcommands, flag values, Git branches, and more, not just a long list of flags. See how to get your tools set up [here](#generate-external-command-definitions-and-completions).

## Less transpose, more records <JumpToc/>

Sometimes you have a record and would quite like to keep having a record. No quick trip through `transpose`, no putting it all back together afterward. Thanks to [@fdncred](https://github.com/fdncred), the new `record where`, `record each`, `record walk`, and `record apply` commands let you work with fields directly.

Keep only the fields you want, change keys and values together, or walk through nested data to redact passwords and tokens. You can also give different fields their own conversions in one go:

```nushell
{age: '42', email: 'A@B.COM'} | record apply {age: {into int}, email: {str lowercase}}
```

They work on table rows too. Take a look at the examples [here](#work-directly-with-records-using-the-new-record-commands), and give your transpose pipeline a well-earned break.

## at-last.env <JumpToc/>

That `.env` file sitting in your project can finally come along without a homemade parser. Thanks to [@fdncred](https://github.com/fdncred), Nushell now reads and writes dotenv files, including names such as `.env.local` and `prod.env`. Loading one is as simple as:

```nushell
open .env | load-env
```

Quoted values, multiline values, comments, and variable expansion are supported, without executing commands from the file. Environment conversions now also run when you load variables, so a string `PATH` becomes a list without the extra conversion dance. Read more about dotenv support and the related environment changes [here](#read-and-write-dotenv-files-with-automatic-environment-conversion).

## Just my type <JumpToc/>

Ever copied the same large record type into three different command signatures? Give it a name instead. Thanks to [@fdncred](https://github.com/fdncred), the new `type` keyword lets you define reusable type aliases:

```nushell
type Point = record<x: float, y: float>
type Polygon = list<Point>

def first-x [poly: Polygon]: nothing -> float { $poly.0.x }
```

Use them in your annotations, build aliases out of other aliases, and export them from modules for other scripts to use. Less repeating yourself, more knowing what that list of records is supposed to represent. More details are [here](#name-reusable-types-with-type).

::: warning Breaking change
`type` is now a reserved keyword, so commands, aliases, or externs you defined with that name need renaming. To call an external command named `type`, use `^type`; to look up a command in Nushell, use `which`.
:::

# Changes <JumpToc/>

## Breaking changes <JumpToc/>

### `ps` lists every process and reports the same columns on every platform <JumpToc/> <PrBy :pr="19145" user="fdncred" />

`ps` now lists every process on macOS (including zombies) and Windows (except the System Idle Process), including other users' and protected processes. Rather than leaving out a process when some information is unavailable, it returns null for those values. On macOS, for example, the CPU, memory and thread values for other users' processes are null unless you run as root.

Both `ps` and `ps -l` now return the same columns on every platform, with null for values a platform or process doesn't provide:

- `ps`: `pid ppid name user status cpu cpu_time mem`
- `ps -l` adds: `virtual private command exe start_time user_id process_group_id session_id priority nice threads read written cwd environment`

The new `cpu_time` column reports total CPU time, while `private` reports memory used only by that process—the value Activity Monitor and Task Manager show as "Memory". The `nice` column holds the nice value, or the priority class mapped onto the nice scale on Windows. The `read` and `written` columns report bytes of storage I/O since the process started (all I/O on Windows), and `exe` holds the executable's path. Platforms previously missing `user`, `user_id`, `process_group_id`, `session_id`, `threads`, `cwd` or `environment` now provide them, as do the BSDs for `start_time`.

Scripts using the old column layout may need updating: `user` is now included in plain `ps`, `virtual` is only available with `ps -l`, and `process_threads` has been renamed to `threads`. The `working` column, which always matched `mem`, and `paged` have been removed. Use `private` for memory used exclusively by a process.

On Linux, `cpu` is now measured to the nanosecond instead of in 10% steps, and `name` is no longer truncated to 15 characters when argv[0] or the executable provides the full name. For processes you can't read—usually other users' processes unless you are root—`cwd` and `environment` are null; `cwd` previously returned an empty string.

On Windows, `ps` now reports `status` as `Running`, `Sleeping` or `Suspended`. The old `user_sid` column is replaced by `user_id`, which holds the SID string, such as `S-1-5-18`. The `virtual` column now means virtual address space size, matching other platforms, and `priority` reports the base priority (8 for normal priority). The `nice` value maps priority classes as libuv and Node.js do: normal is 0, high is -14 and idle is 19. The `process_group_id` identifies the console process group created with `CREATE_NEW_PROCESS_GROUP`, to which `GenerateConsoleCtrlEvent` sends Ctrl+Break.

On macOS, `cwd` now reports the current working directory rather than the directory where the process started. The `status` column uses `Sleeping` instead of `Sleep` and `Waiting`, matching other platforms, and reports zombies as `Zombie`. The `kernel_task` process (pid 0) is now listed, as in Activity Monitor.

On FreeBSD, NetBSD and OpenBSD, zombies and other processes whose arguments can't be read are now listed under the kernel's process name. FreeBSD's `cpu` measurement now includes threads that start or exit during the sample, and OpenBSD's `virtual` value is no longer always 0. On both Windows and the BSDs, `command` now replaces newlines and tabs in arguments with spaces, as it already did on Linux and macOS.

When filtering or sorting, account for the newly visible null values. Null sorts after every number, so drop nulls before selecting the highest CPU users: `ps | compact cpu | sort-by cpu | last 3`. Matching a nullable text column with `=~` is an error, so similarly use `ps | compact status | where status =~ Run`.

### `group-by --to-table` keeps original key types <JumpToc/> <PrBy :pr="18853" user="fdncred" />

`group-by --to-table` no longer converts group keys to display strings. The group columns keep the original type, and rows are grouped by typed value identity (same type and payload), not by how the value would print.

```ansi :no-line-numbers
[0m│ [0;1;38;5;2m1[0m │ [0;38;5;6m1,0 MB [0m│ [table 1 row] │[0m
```

Default `group-by` (record output) is unchanged: keys are still display strings, `"true"` and `true` still share a group, and filesize/datetime still follow config. Use `--to-table` when you need the original type.

This is a breaking change for scripts that assumed `--to-table` keys were strings (`str replace`, `into filesize` after stringify, string compares). `"true"` and `true` are now separate `--to-table` groups.

### Retrieve multiple cell paths with `get ...$paths` <JumpToc/> <PrBy :pr="18220" user="mvanhorn" />

`get` now accepts spread cell paths with `get ...$paths`, returning a list with one value per path whenever a spread argument is used. Its signature changes from `get <cell_path> ...(rest)` to `get ...(rest)`, so calling `get` without arguments is no longer a parse error. Instead, it returns its input, or reports `Pipeline empty` when there is no input.

### Pass column names directly to `update cells` <JumpToc/> <PrBy :pr="19125" user="Shub3am" />

`update cells` now accepts column names as rest arguments, matching `select`, `reject`, and the `into` commands. The `--columns` (`-c`) flag is deprecated but still works, with a warning on first use. Replace the flag and list with column names after the closure:

```nushell
# before
[[name val1 val2]; [foo 1 4] [bar 8 3]] | update cells -c [val1 val2] { $in * 2 }
# after
[[name val1 val2]; [foo 1 4] [bar 8 3]] | update cells { $in * 2 } val1 val2
```

### Assigning `$env.config.keybindings` and `$env.config.menus` replaces the list <JumpToc/> <PrBy :pr="19418" user="kronberger-droid" />

Breaking: `$env.config.keybindings = [...]` and `$env.config.menus = [...]` now replace the whole list, including nushell's default menus and the keys that open them (Tab and Shift+Tab completion, Ctrl+Space, F1 help, Ctrl+X and Ctrl+Z paging, the Ctrl+R history menu).
If your config assigns either list, or sets `keybindings` or `menus` inside a `$env.config = {...}` record, switch to `++=` or Tab stops completing.
Reedline's own bindings (movement, editing) are not part of the list and stay.

```nu
$env.config.keybindings ++= [{ name: my_binding, modifier: control, keycode: char_t, mode: emacs, event: { send: clearscreen } }]
```

To get the defaults back in a running shell, assign them again from a clean `nu -n`:

```nu
$env.config.keybindings = (^$nu.current-exe -n -c '$env.config.keybindings | to nuon' | from nuon)
$env.config.menus = (^$nu.current-exe -n -c '$env.config.menus | to nuon' | from nuon)
```

Filtering a list now removes what it drops, and `= []` clears either list.
When several keybindings bind the same key in the same mode, or several menus share a name, the last one wins.
A keybinding's `name` is only a label, so sharing one between keys no longer warns.
To unbind a key that reedline itself binds, add an entry for it with `event: null`.

### Stricter input and argument checks for `save`, `%(...)` and plugin `call_decl` <JumpToc/> <PrBy :pr="19351" user="fdncred" />

Calls made through `save`, `%($cmd)` and a plugin's `call_decl` now enforce the same input and argument rules as direct command calls. Scripts and plugins that relied on these checks being skipped may need updating:

- `save` checks a custom `to <ext>` converter's input type. A converter whose signature doesn't cover the data now errors instead of running. Built-in `to` commands reject the same inputs as before, but with `Input type not supported` instead of their own message. `open` and `http` are unchanged, since they hand converters an untyped byte stream.
- `save` keeps a custom `to <ext>` converter's `$env` changes inside it unless it is `def --env`, the same as `... | to <ext>`.
- `%($cmd)` checks its input and arguments as a direct call does. Spreading a list into a command without a rest parameter is an error instead of being silently dropped.
- A plugin's `call_decl` checks the input type, including empty input. `'a' | example call-decl uniq` now errors with `Input type not supported`, and `example call-decl 'str join'` with `Pipeline empty`.
- `view ir --json` no longer has an `ast` field in `ir_block`. It was always `null`.

#### Embedders and out-of-tree `Command` implementations

`engine::Call::new`, `Command::requires_ast_for_arguments`, `engine::Call::positional_nth` and the `ast` fields on calls and arguments are gone. Build an `ir::Call` with `ir::Call::build` and run it with `nu_engine::eval_ir_call`; the PR description has the full migration table. Plugins implementing `PluginCommand` are not affected.

### Other breaking changes <JumpToc/>

- `not` now has the precedence `help operators` lists: `not $a == $b` means `not ($a == $b)`. Before, `not` applied to the next value only. <PrOther :pr="19271" />
- `-$x` and `-(expr)` negate their value, also as a flag's value or an argument after `--`. Before, `-$x` was the string `"-$x"` and `-(2 + 3)` the string `"-5"`. Arguments to external commands are unchanged. <PrOther :pr="19271" />
- An integer literal too large for 64 bits, such as `9223372036854775808`, is an error. Add `.0` to write a float. <PrOther :pr="19271" />
- Filesize and duration literals that don't fit are a parse error (`nu::parser::literal_too_large`) instead of saturating to the largest value. <PrOther :pr="19271" />
- A word written like a date that isn't a valid date, such as `2023-02-29`, is an error. <PrOther :pr="19271" />
- `INF`, `Nan`, `Infinity` and other spellings of special floats are strings. Use `inf`, `nan` or `NaN`. `from nuon` reads them the same way. <PrOther :pr="19271" />
- A record or table literal that names a field twice is a parse error. <PrOther :pr="19271" />
- `[1 2]]` is an error instead of `[1, "2]"]`. <PrOther :pr="19271" />
- In a custom command, repeated parameter or flag names, repeated short flags, a parameter after `...rest`, and a `--help` flag are errors. <PrOther :pr="19271" />
- `while` and `loop` can't be piped, like `for`. <PrOther :pr="19271" />
- `unlet` errors on constants and on `$in`. <PrOther :pr="19271" />
- Assigning to a `mut` variable inside a `where` condition is an error; the assignment never took effect. <PrOther :pr="19271" />
- `hide` inside a block (`do { }`, `if`, a command body) now hides the name only in that block. <PrOther :pr="19415" />
- `source` of a file sourced before in a block that has ended, such as `do { source x.nu }; source x.nu`, now defines the file's commands and variables again. <PrOther :pr="19415" />
- A variable from a sourced file can now be used inside a closure, as in `do { source x.nu; $x }`. <PrOther :pr="19415" />
- `run` keeps a script's commands, including `main`, and its variables inside the script. Previously they stayed defined in the caller after `run`, and a `main` from `run` ran a second time when the calling script ended. <PrOther :pr="19415" />
- A pipe or redirection in an alias is now a parse error. Previously `alias q = ls | length` passed `|` and `length` to `ls` as arguments. Use `def` for a pipeline. <PrOther :pr="19415" />
- Scripts, modules and config files that start with a UTF-8 byte-order mark now run. <PrOther :pr="19415" />
- Breaking change. Module directories with a dot in their name now keep the full name. `use a.b` creates module `a.b` (commands like `a.b foo`) where it used to create `a` (`a foo`). The same goes for overlays, so `overlay use a.b` now gives overlay `a.b`. A directory named `foo.nu/` is now `foo.nu` instead of `foo`. Scripts that call these commands by the short name need updating. ([#19390](https://github.com/nushell/nushell/pull/19390))

## Additions <JumpToc/>

### Work directly with records using the new `record` commands <JumpToc/> <PrBy :pr="19190" user="fdncred" />

Added `record where`, `record each`, `record walk` and `record apply` to filter fields, transform keys and values, process nested values, and apply field-specific conversions without converting records to tables and back. Each command also accepts a table and streams one record per row. Run `record` to see help listing the subcommands.

The following examples show how to filter and transform records, redact nested values, and convert fields in records or table rows.

```ansi :no-line-numbers
[0m╭───┬────╮[0m
[0m│ [0;1;38;5;2mA[0m │ 10 │[0m
[0m│ [0;1;38;5;2mB[0m │ 20 │[0m
```

### Name reusable types with `type` <JumpToc/> <PrBy :pr="19223" user="fdncred" />

Nushell now supports type aliases with `type Name = <type>`, letting you reuse descriptive names instead of repeating type annotations. Aliases can also refer to other aliases, including inside generic types:

```nushell
type Point = record<x: float, y: float>
type Polygon = list<Point>

def first-x [poly: Polygon]: nothing -> float { $poly.0.x }
```

Use aliases in parameters, flags, rest and closure parameters, input/output types, and `let`/`mut`/`const` annotations. Help, command introspection, and errors show the expanded type. Completers stay on parameters, as in `def paint [color: Color@[red green blue]]`, rather than on the alias itself.

Define aliases before using them; self-references are not allowed. Aliases are local to a block and persist across REPL lines. Export module aliases with `export type`, then import them by name, in a list, or with `*`; a bare `use mod` does not import them.

`type` is now reserved. Scripts defining a command, alias, or extern named `type` fail with "Can't use parser keyword `type` as command name" until that definition is renamed. On macOS, a bare `type ls` no longer runs `/usr/bin/type`; use `^type` or Nushell's `which`.

### Catch undeclared flags with `extern --strict` <JumpToc/> <PrBy :pr="19313" user="fdncred" />

`extern --strict` and `export extern --strict` now reject undeclared flags with a parse error and a "Did you mean" hint for matching declared flags, helping catch typos before running an external command. Positional arguments, `--` and the arguments after it still reach the command. `--help` is always allowed; `-h` must be declared. Externs without `--strict` continue to accept undeclared flags.

Unknown flags inside a declared flag's value, as in `cmd --x (ls --bogus)`, are now reported for externs and `def --wrapped` commands instead of silently dropping the error and passing `--x` without its value.

### Structured data from external commands <JumpToc/> <PrBy :pr="19316" user="fdncred" />

The new `@structured [args] { decode }` attribute lets an extern return structured data without repeating output-format flags and decoding commands. When its output is piped into an internal command or saved with `let`, Nushell adds the specified arguments and decodes the output with the block. At the terminal, through `print`, when redirected to a file, or when piped into another external command, the tool's own output is unchanged.

```nushell
@structured [--porcelain] { lines | parse --regex '^(?<status>..) (?<file>.+)$' }

git status | where status =~ M | get file   # runs `git status --porcelain` and parses it
git status                                  # git's own text
```

### Generate external command definitions and completions <JumpToc/> <PrBy :pr="19314" user="fdncred" />

The new `generate completions` command generates a module of `extern` definitions and completers from carapace specs, fish or zsh completions, man pages, or `--help` text. Save the output and load it with `use` or `source`, or place it in an autoload directory:

```nushell
generate completions git | save ($nu.user-autoload-dirs | first | path join git-completions.nu)
```

When using `use`, choose a filename other than the tool's name, such as `git-completions.nu`. Generated modules provide flag-value and argument completions where the source supports them, including fixed lists, git branches, remotes and tags from fish completers, users and hosts, and native completions from Cobra-based tools such as gh, docker and kubectl.

By default, the first source that knows any flags is used, in the order carapace, fish, zsh, man, then help. Use `--source all` to merge sources. Carapace, fish and zsh provide subcommand trees; man and help provide flags for the named command. You can also pipe source text, as in `^git status -h | generate completions "git status" --source help`.

Flag-name completion also no longer lists a flag twice when an extern with `@complete external` declares it and the external completer suggests it too.

### Smaller table output and ANSI optimization with `ansi opt` <JumpToc/> <PrBy :pr="19340" user="fdncred" />

Tables using the default colors now contain fewer escape sequences, reducing output size by 19% for `ls`, 28% for a nested table, and 43% for a 300-row stream. Their appearance is unchanged, even when an individual line is extracted and printed on its own.

The new `ansi opt` command shortens ANSI escape sequences in strings, binary data, and byte streams without changing their terminal appearance. Use `--stats`, `--diff`, `--explain`, `--hotspot`, `--show`, or `--html` to inspect the changes as records, tables, visible escape sequences, or an HTML report. Optimization is explicit; Nushell does not automatically rewrite other output at print time.

### Custom converters and commands work in more indirect calls <JumpToc/> <PrBy :pr="19351" user="fdncred" />

Running a command by id now takes the same path as a compiled call, so `save`, `%($cmd)`, `http`, `open` and a plugin's `call_decl` check input types and bind arguments the way a direct call does.

This also makes custom commands usable in more places. The `http` commands can now convert a response with a custom `from <ext>` command, as `open` already could. When `save` uses a custom `to <ext>` converter, it now binds that command's flags and defaults. Plugins can also use `call_decl` to call a custom command.

### Read and write dotenv files with automatic environment conversion <JumpToc/> <PrBy :pr="19391" user="fdncred" />

Nushell now supports `from dotenv` and `to dotenv`. `open .env` also recognizes names such as `.env.local` and `prod.env`, returning a record, while saving a record to these files writes dotenv text. Use `open .env | load-env` to load variables from a dotenv file.

Dotenv parsing supports quoted and multiline values, comments, optional `export`, and variable expansion using earlier keys or environment variables, without executing commands. Serialization applies environment string conversions, including joining a `PATH` list with the path separator, and quotes and escapes values for reading back.

`load-env`, `with-env` and `FOO=bar cmd` now apply `$env.ENV_CONVERSIONS` to the variables they set, and a string `PATH` becomes a list. The `$env.ENV_CONVERSIONS = $env.ENV_CONVERSIONS` line after `load-env` is no longer needed. Pass `--no-convert` to set the values as given.

A text file named like `.env` that isn't `KEY=value` lines, such as an autoenv shell script, now fails to open with a parse error. Use `open --raw .env` to read it as text. Recognized extensions retain their formats, so `.env.json` still opens as JSON. `save` now matches extensions regardless of case, so `save data.JSON` writes JSON.

### Use `first` and `last` in constant expressions <JumpToc/> <PrBy :pr="19399" user="Tyarel8" />

The `first` and `last` commands now work in a `const` context, allowing you to use them when defining constants. Using `last` on an unbounded range (e.g. `1.. | last`) now returns an error instead of hanging indefinitely.

For example, you can extract a username from your home directory when defining a constant:

```nushell
# Get username from home directory
const $USER = $nu.home-dir | path split | last
```

### Filter datetimes with `older-than` and `newer-than` <JumpToc/> <PrBy :pr="19397" user="fdncred" />

The new `older-than` and `newer-than` operators make filtering by age simpler. `ls | where modified older-than 2wk` keeps files last changed more than two weeks ago, and `newer-than 2wk` keeps files changed since then. With a datetime on the right, they work like `<` and `>`: `$date older-than 2024-01-01`. Both comparisons are strict, excluding equality, and are listed in `help operators`.

Duration comparisons use the current time, so they cannot be used in `const`, parameter defaults, or match patterns; datetime-to-datetime comparisons remain available there. Either operator returns `nothing` if either operand is `nothing`.

Comparing a datetime with a duration using `<`, `<=`, `>` or `>=` now suggests `older-than` or `newer-than` in the error.

### Live status line and interruptible math reductions <JumpToc/> <PrBy :pr="19403" user="fdncred" />

The REPL now shows a status line beneath the line being edited, providing feedback as you type. It displays the first parse or type error or, when there is none, the command signature with the current parameter emphasized, the pipeline's output type, and a preview of lines built only from const commands. For example, `"a,b" | split row ","` shows `= [a, b]`. The status line is erased when the line runs.

Use `$env.config.status_line` to control what appears: `enable` controls the whole status line, while `errors`, `signature`, `type`, and `preview` control individual parts.

Ctrl+C now stops math reductions over large ranges, such as `1..10000000000 | math sum`, with `Operation interrupted`. In a script or `nu -c`, it also stops const evaluations such as `const x = (1..10000000000 | math sum)`.

## Performance <JumpToc/>

### Faster parsing and improved parser diagnostics <JumpToc/> <PrBy :pr="19138" user="fdncred" />

Nushell now parses real scripts about 1.33x faster, reducing parsing time for REPL input, scripts, modules, configuration files, and the standard library. This shortens startup and script loading without changing how valid code is parsed.

Error reporting is also improved. Invalid `break` or `continue` statements in closures or `def` bodies inside `catch` or `finally` clauses are now reported during parsing rather than failing at runtime. The "Extra tokens" error for `ls |; ls` now points at the `;`, and an unclosed list reports its "Unclosed delimiter" error only once.

Inside brackets, `#` starts a comment only when immediately preceded by whitespace. `[voilà#tag]` now parses as `["voilà#tag"]` instead of producing an "Unclosed delimiter" error. Additionally, `def --help foo [] { ... }` shows help without defining `foo`, preventing a later call to `foo` from crashing the shell. `view ir` now separates items in list and record patterns with commas.

### Faster startup and reliable prompt updates <JumpToc/> <PrBy :pr="19236" user="fdncred" />

Nushell starts faster and uses about 3 MiB less memory per process on Apple silicon Macs. On all architectures, the startup banner avoids computing the welcome message when it only prints the startup time. Measured startup improvements with the default config are shown below; `$nu.startup-time` is measured the same way as before.

| default config, from `~`                 | main     | this PR  |
| ---------------------------------------- | -------- | -------- |
| launch to first prompt                   | 15.70 ms | 13.10 ms |
| `$nu.startup-time`                       | 8.03 ms  | 7.36 ms  |
| instructions retired by the first prompt | 149.3M   | 119.8M   |

On all architectures, `date to-timezone` now accepts IANA time zone names in any letter case, for example `date now | date to-timezone america/new_york`. Previously, some lowercase names were rejected as invalid.

Prompt updates from background jobs using `commandline set-prompt` are no longer lost when the jobs finish before the prompt is drawn. This applies to jobs started from `pre_prompt` or `env_change` hooks or prompt closures such as `$env.PROMPT_COMMAND`, on all architectures. Calling `commandline set-prompt` directly in those hooks or closures also updates that prompt, overriding the corresponding segment's prompt-variable value rather than being replaced by subsequent prompt evaluation.

### Other performance improvements <JumpToc/>

- Closures that call `each`, `where`, `update` or another command that takes a closure run much faster. <PrOther :pr="19394" />
- Calls to built-in commands inside loops and closures are faster. <PrOther :pr="19394" />
- `into datetime`, `format date`, `date humanize` and `date to-timezone` read RFC 3339 date-times (`2025-04-18T04:04:32-07:00`) several times faster. <PrOther :pr="19394" />

## Deprecations <JumpToc/>

### Deprecated commands, flags, and compatibility support removed <JumpToc/> <PrBy :pr="19382" user="fdncred" />

Commands and options deprecated in Nushell 0.112 or earlier have been removed. Update affected scripts and custom completers to use their replacements:

- `get`, `select`, and `reject` no longer accept `--ignore-errors (-i)`. Use `--optional (-o)`.
- `get --sensitive (-s)` is removed. Cell paths are case-sensitive by default; add `!` after a member to make it case-insensitive.
- `filter` is removed. Use `where`, which accepts the same closures, including closures stored in variables.
- Custom completer results no longer support `positional`. Use `completion_algorithm: substring` instead. A completer returning `positional: false` now gets prefix matching.

The `date format` and `let-env` stubs and removal hints for `fetch`, `post`, and `benchmark` have been deleted. These commands were removed in 2023. `let-env FOO = 1` now fails with "Assignment operations require a variable", and `date format '%Y'` with "Extra positional argument". Use `$env.FOO = 1` and `format date`, respectively. Existing search terms still suggest `http get` for `fetch`, `http post` for `post`, and `timeit` for `benchmark`.

Nushell no longer converts a pre-0.93 `plugin.nu` into `plugin.msgpackz`. Setups with only `plugin.nu` start with no plugins; register them again with `plugin add`.

`default` no longer warns when a closure is passed directly as `$var`, and its help now clarifies the unchanged behavior: `default $closure` uses the closure itself as the default value, while `default { ... }` evaluates the closure lazily.

## Other changes <JumpToc/>

### Clearer, correctly aligned `char --list` output <JumpToc/> <PrBy :pr="19091" user="pickx" />

`char --list` now groups alternate names for the same character in a new `aliases` column, reducing the table from 118 entries to 56 and making it easier to browse. Platform-dependent characters, such as path separators, remain separate entries.

The table also stays correctly aligned when displaying control characters that previously caused misalignment.

### `dc-glob` follows `nu-glob's` rules in every command, with `{a,b}` added <JumpToc/> <PrBy :pr="19422" user="fdncred" />

<ExperimentalOption option="dc-glob" />

With the `dc-glob` experimental option enabled, globbing now follows `nu-glob`'s rules consistently across commands. Patterns such as `rm *`, `cp *`, `mv *` and `du *` no longer match dotfiles. Recursive removal also respects the starting directory: `rm -r **` no longer reaches the current directory, while `rm -r */**` removes directories below the top-level ones without removing those top-level directories themselves.

Both `ls **` and `ls dir/**` list directories below the starting point, rather than the starting directory itself, and follow directory symlinks. The `glob` command now uses the same rules as `ls`: `glob **` and `glob dir/**` list directories below the prefix, `glob **/*` lists everything below it, and `glob */` lists directories only. The previous wax-specific `<x:n,m>` repeats and `\` escapes are no longer supported.

Brace alternatives such as `{a,b}` now work in every command, so `ls *.{rs,toml}` matches both extensions. Braces without a comma remain literal, and arguments without `*`, `?` or `[` aren't expanded, leaving `^git show HEAD@{1}` unchanged. Since an argument can't start with `{`, use `./{src,tests}/*.rs` for alternatives at the beginning of a path. Paths such as `/abs/a]c` and `a{b}` refer to the files they spell.

Exclusion patterns are consistent too: `du --exclude '*.txt'` once again excludes `.txt` files at any depth, as it does without `dc-glob`. Both `du --exclude` and `glob --exclude` accept `{a,b}` alternatives, as does `watch --glob`.

Malformed patterns such as `***`, `a**` and `[a` now produce an error. In particular, mistyping `rm ***` no longer deletes everything below the current directory.

### Helix mode: h/l in menus, match commands under m and more text objects <JumpToc/> <PrBy :pr="19175" user="kronberger-droid" />

In Helix mode, `h` and `l` now step through an open menu, and `l` accepts a history hint, matching the arrow keys and vi's `h`/`l` behavior. The new match commands under `m` let you select inside or around a pair, add a pair around the selection, and delete or replace the nearest pair. The cursor also no longer appears at the start of the next line while the prompt waits for the terminal's position report.

Text object edit commands now accept more values in the keybinding config. Alongside `word`, `bigword`, `brackets` and `quotes`, `object_type` accepts individual pairs: `parentheses`, `square_brackets`, `curly_brackets`, `angle_brackets`, `single_quotes`, `double_quotes` and `backticks`. Custom pairs can be specified as records, such as `{ left: "|", right: "|" }`, and `brackets` now includes `<>`.

`CutTextObject`, `CopyTextObject` and the new `SelectTextObject` accept an optional `check_next` setting, which defaults to `true`. When the cursor is outside any match, these commands act on the next one. The new `AddTextObject` and `RemoveTextObject` commands take `object_type`, while `ReplaceTextObject` takes `old` and `new`. These three commands require a single pair, so using `word`, `brackets` or `quotes` produces an error.

For example, these keybinding events select inside parentheses, wrap the selection in asterisks, and replace parentheses with square brackets:

```nushell
{ edit: SelectTextObject, scope: inner, object_type: parentheses }
{ edit: AddTextObject, object_type: { left: "*", right: "*" } }
{ edit: ReplaceTextObject, old: parentheses, new: square_brackets }
```

### IPv6 zone IDs in HTTP commands <JumpToc/> <PrBy :pr="19213" user="skyfireitdiy" />

`http get`, `http post`, and the other `http *` commands now support `http://` URLs with IPv6 zone IDs, such as `http get 'http://[fe80::13%eth0]'`, allowing requests to link-local addresses on a specific network interface. The RFC 6874 encoded form, such as `[fe80::1%25lo0]`, is also supported. Plain IPv6 requests such as `http get 'http://[::1]:8080/a.txt'` now work as well; previously these URLs failed to parse or resolve.

### `oneof` literals prefer matching types over strings <JumpToc/> <PrBy :pr="19238" user="fdncred" />

### JSON parsing accepts a leading UTF-8 byte order mark <JumpToc/> <PrBy :pr="19383" user="jaeminbird" />

### Flags now work with dynamic builtin calls <JumpToc/> <PrBy :pr="19404" user="fdncred" />

`%$cmd` and `%($cmd)` now pass flags to the builtin selected at runtime. For example, `let cmd = "sort"; [1 3 2] | %$cmd --reverse` returns `[3, 2, 1]`. ### Breaking changes to flag handling in dynamic builtin calls

Unquoted flag-like arguments in `%$cmd` and `%($cmd)` calls are now interpreted as flags. `let cmd = "echo"; %$cmd --foo` previously printed `--foo` but now produces an unknown-flag error, like `echo --foo`; quote the argument to pass it as a string. ### Math reducers now aggregate table columns <JumpToc/> <PrBy :pr="19414" user="fdncred" />

`math sum`, `math avg`, `math product`, `math max`, `math min`, `math median`, `math mode`, `math stddev` and `math variance` with column arguments now reduce the named columns across all table rows and return one record, equivalent to `select <columns> | math <op>`. For example, `ls | math sum size` gives `{size: ...}` instead of returning the table unchanged. Record input behaves as before: list fields are reduced and scalar fields remain unchanged.

### Math reducers now reject table columns containing lists

A table column that holds lists now produces an error, as it does for `select a | math sum`. Previously, `[[a]; [[1 2]] [[3 4]]] | math sum a` reduced each row's list to `[[a]; [3], [7]]`. To retain that row-by-row behavior, use `update a { math sum }`.

### `table --collapse` keeps rows aligned and respects `--width` <JumpToc/> <PrBy :pr="19424" user="fdncred" />

`table --collapse` now keeps each record's cells aligned when values contain nested lists, nested tables, multiple lines, or text wrapped by `--width`. Tables also stay within the requested width when using custom `table.padding` or empty nested lists.

This also fixes alignment for multiline record keys, empty values with zero padding, and the `restructured` theme, and removes a stray space that shifted some nested values in the `none` and `psql` themes.

### Invalid keybindings and menus are rejected on assignment <JumpToc/> <PrBy :pr="19438" user="kronberger-droid" />

Assigning `$env.config.keybindings` or `$env.config.menus` now produces an error if an entry can't be read, leaving the old list unchanged. This validation covers a keybinding's `modifier`, `keycode` and `mode`, and a menu's `layout`, `input_mode` (or `only_buffer_difference`) and `output_mode`. Menus without a `layout`, such as `type: {}`, are also rejected. Previously, invalid entries were accepted and failed on every prompt. In `config.nu`, a rejected assignment stops the lines after it from running.

The new `config default` command returns the default configuration as a record. Since sourcing a config again appends its `++=` entries each time, while `=` replaces the list and drops the defaults, start from the defaults before adding custom entries to keep the list stable:

```nu
$env.config.keybindings = (config default).keybindings
$env.config.keybindings ++= $custom
```

### More date formats and more reliable datetime parsing <JumpToc/> <PrBy :pr="19398" user="fdncred" />

`into datetime`, `format date`, `date humanize`, `date to-timezone` and `detect type` now read more date formats from strings. These include Unix timestamps such as `@1745000000`, ISO week dates such as `2025-W16-5`, ordinal dates such as `2025-108`, and Apache log timestamps. IANA time zones can be included in several forms: `2025-04-18 04:04:32 America/New_York`, `2025-04-18T04:04:32[America/Chicago]` and `TZ="Europe/Paris" 2025-04-18 04:04`.

Relative dates such as `tomorrow 10am`, `3 days ago`, `next friday` and `2025-04-18 + 2 days` are also supported. These follow GNU `date -d` conventions rather than `date from-human`: `today` means now, including the time of day, and a bare unit such as `month` or `week` means one unit from now, whereas `date from-human` rejects a bare unit. A weekday such as `next friday` resolves to midnight rather than retaining the current time of day. The phrase `in 2 days` remains supported only by `date from-human`.

Timezone handling is more consistent. Offsets such as `+0530` keep their minutes, even with a zone name in parentheses after them (`+0530 (IST)`), and US zone names in RFC 2822 dates, such as `PDT` and `EST`, use their own offset instead of local time. Local times at daylight-saving transitions now resolve the same way as times with an explicit IANA zone. In Chicago, for example, the repeated time `2025-11-02 01:30` selects the earlier occurrence, -05:00 rather than -06:00. The skipped time `2025-03-09 02:30` represents the same instant as before, but is now shown as 03:30 -05:00 rather than 02:30 -06:00.

Invalid dates such as `2025-02-30` now produce an error instead of becoming February 28, while February 29, 2000 parses correctly. Strings that previously made `into datetime` panic, such as `2025-04-18T04:04:32.Z`, now either parse or return an error. Two-digit years consistently map to 1969–2068 rather than the 100 years around the current year, so years 69 through 75 now mean 1969 through 1975; `1/1/70`, for example, is 1970 instead of 2070.

Some strings are no longer interpreted as dates: decimals such as `3.14`, times written with units such as `10h36m28s`, POSIX zone offsets such as `UTC+3`, a month name after a time such as `10:00 DEC`, and forms such as `1996.07.10 AD at 15:08:56 PDT`. Signed numbers and five-digit numbers, such as `-0500` and `10000`, are now read as nanosecond timestamps like other integers, rather than as the years 500 and 10000.

- `into int` and `into float` conversion errors now name the right direction (`can't convert string to int`), point at the input value rather than the command, and carry the parse reason as help text. ([#19363](https://github.com/nushell/nushell/pull/19363))
- `split column` now rejects duplicate column names with a `column_defined_twice` error pointing at both uses, instead of silently overwriting the earlier column. ([#19362](https://github.com/nushell/nushell/pull/19362))
- `fill --alignment` now errors on an unknown alignment instead of silently left-aligning; valid values are `left`, `right`, `center`/`middle` and `centerright`/`middleright`. ([#19361](https://github.com/nushell/nushell/pull/19361))
- Fixed explicit relative paths in experimental `dc-glob`: patterns such as `./*.txt`, `../*.txt`, and `../**` now search the intended directory. Exact paths such as `.` and `..` also return their matching directory. ([#19348](https://github.com/nushell/nushell/pull/19348))
- Fixed a type mismatch error when a `let` without a type annotation gets a list from chained `update` calls on a custom command's output. ([#19379](https://github.com/nushell/nushell/pull/19379))
- Ranges with invalid step sizes don't cause an overflow anymore ([#19385](https://github.com/nushell/nushell/pull/19385))
- Duplicate-key errors from record literals that use `...` spreads now point at the right places. For `let a = {s: 1}; {...$a, s: 3}`, the error underlines `s: 3` as the redefinition and `...$a` as where `s` was first defined, instead of the whole record and the original `{s: 1}`. These errors also explain that a record literal can't repeat a key, even one brought in by a spread, and suggest `merge` or `update` to replace a field. ([#19352](https://github.com/nushell/nushell/pull/19352))
- Fixed `update cells` hiding errors from its closure. An error inside the closure is now raised instead of being stored as the cell value. ([#19389](https://github.com/nushell/nushell/pull/19389))
- `rm` no longer removes hidden files through a glob, at any depth, unless the pattern starts a name with `.` or `--all` is given. Before, `rm **/*.txt` also removed `.txt` files inside hidden directories, and with the `dc-glob` experimental option `rm *` removed dotfiles. ([#19421](https://github.com/nushell/nushell/pull/19421))
- `grid` now uses layouts that fill the full width, so it no longer errors on a grid that fits exactly and can print fewer rows. ([#19409](https://github.com/nushell/nushell/pull/19409))
- `date to-timezone` preserves seconds in numeric offsets such as `+05:30:15` and rejects invalid suffixes and separators such as `+05:30XYZ`, `+05:`, and `+05:::30`. Historical time zones with second-level offsets round correctly with `date floor` and `date ceil`. ([#19434](https://github.com/nushell/nushell/pull/19434))

# Notes for plugin developers <JumpToc/>

## Deprecated APIs removed for plugin authors

Several deprecated Nushell APIs have been removed. Plugin authors using these APIs need to update their code to the available replacements:

- Replace `ShellError::GenericError` with `ShellError::Generic(GenericError)`.
- Replace `PipelineData::metadata()` with `metadata_ref()`, `metadata_mut()`, or `take_metadata()`.
- Replace `EngineState::current_work_dir()` and `StateWorkingSet::get_cwd()` with `EngineState::cwd()` or `cwd_as_string()`.
- Replace `ast::Call::positional_nth()` and `positional_len()` with `positional_iter()`.
- The unused `ShellError::DeprecationWarning` is removed.

`CustomValue::is_iterable()` is no longer deprecated and remains available.

## New comparison variants

`nu_protocol::ast::Comparison` has two new variants, `OlderThan` and `NewerThan`. A `match` on `Comparison` without a wildcard arm needs arms for them, and `CustomValue::operation` receives them when a custom value is on the left.
