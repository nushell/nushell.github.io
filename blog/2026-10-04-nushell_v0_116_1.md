# Nushell 0.116.1

Today, we're releasing version 0.116.1 of Nu. This patch release improves TUI widgets with live stream updates, customizable borders and titles, and more reliable pane resizing, while fixing completions and refining startup-time reporting.

# Where to get it

Nu 0.116.1 is available as [pre-built binaries](https://github.com/nushell/nushell/releases/tag/0.116.1) or from [crates.io](https://crates.io/crates/nu). If you have Rust installed you can install it using `cargo install nu`.

As part of this release, we also publish a set of optional [plugins](https://www.nushell.sh/book/plugins.html) you can install and use with Nushell.

# Changes <JumpToc/>

## Deprecations

### Deprecation: `tui label --title` is now `tui label --titlebar` <JumpToc/> <PrBy :pr="19102" user="fdncred" />

To put a label in the top bar, use `tui label --titlebar "My app"` instead of `tui label --title "My app"`. The old switch still works but warns on first use and is scheduled for removal in 0.118.0.

## Additions <JumpToc/>

### Widgets can set their border title with `--title` <JumpToc/> <PrBy :pr="19102" user="fdncred" />

Use `--title <text>` to name the border of `tui table`, `tui tree`, `tui select`, `tui log`, `tui preview`, `tui search`, or `tui textbox`. The title replaces the widget's default name, while row counts and status indicators remain visible. For example:

```nu
ls | tui table --title files | tui run
```

The table's border now reads `files (12)` rather than `table (12)` when it has 12 rows. For `tui preview`, the previewed filename follows the custom title, as in `files (Cargo.toml)`; without a file to preview, only the custom title appears. For `tui search`, the title also becomes the default placeholder unless `--placeholder` is set. An empty `--title` is rejected.

### Choose `tui` border lines with `--border` or `$env.config.tui.border_type` <JumpToc/> <PrBy :pr="19100" user="fdncred" />

Bordered TUI widgets now accept `--border <name>` to change their outline. This includes `tui table`, `tui tree`, `tui select`, `tui log`, `tui preview`, `tui search`, `tui textbox`, `tui box`, and the dropdowns opened by `tui menu`. The names match `table --theme` options, and the flag offers completion for valid border names.

```nu
ls | tui table --border rounded | tui run

$env.config.tui.border_type = "double"
ls | tui table | tui run
```

`$env.config.tui.border_type` sets the default for all TUI borders, including menu dropdowns and dialog frames. An individual widget's `--border` overrides it. The default is `single`, which preserves the previous appearance. For example, `rounded` draws `╭─╮`, `double` draws `╔═╗`, and `heavy` draws `┏━┓`; styles such as `basic`, `dots`, and `markdown` are available too.

`none` and `default` are not valid TUI border names. Use `frameless` for an outline with no visible lines: it still occupies one cell, and the widget's title remains visible. When a widget has its own `--border`, its `widgets` record includes the selected border name.

## Bug fixes <JumpToc/>

### TUI widgets now display streamed data as it arrives <JumpToc/> <PrBy :pr="19099" user="fdncred" />

Slow and endless streams now update TUI widgets while `tui run` is open. A log displays each row as it arrives, and a progress bar advances as its input runs instead of starting at 100%:

```nu
1.. | each {|n| sleep 1sec; $n} | tui log | tui run
```

This also works for streams piped into widgets in a child list, such as `tui split [(tail -f app.log | tui log) (ls | tui table)]`.

TUI builders now always output a `tui` value: piping one into a non-TUI command, such as `1.. | tui table | first`, no longer returns the input rows. A TUI value saved with `let` reads its stream on the first run. If the stream finishes, later runs display the same rows; if it stops early, later runs display no rows. When a `tui run` closure, `tui bind`, button, or menu hook returns data, that data replaces the piped data for the rest of the run, without additional rows arriving from the stream.

Streams now keep around 100,000 of their newest rows, dropping older rows in batches of 12,500. Up to 12,499 extra rows can appear between drops, and `tui log --max-lines` can raise the limit further. Piping data into a child list whose widgets all specify `--data` now produces an error instead of silently ignoring the input.

### TUI split panes now resize reliably with keyboard and mouse <JumpToc/> <PrBy :pr="19101" user="fdncred" />

After focusing a `tui split` with Tab, the arrow keys or `h`/`j`/`k`/`l` move its first divider in either direction. Each press moves it one cell on splits up to 100 cells wide or tall when there is room; on larger splits, a press may move it a few cells. This works for both the default side-by-side layout and `--vertical`, including short splits where resizing previously got stuck.

```nu
ls | tui split [(tui table) (tui preview)] | tui run
ls | tui split [(tui table) (tui preview)] --vertical | tui run
```

Dragging a divider with the mouse now places it as close to the pointer as the surrounding panes allow, including dividers between later panes in a split. Resizing preserves at least one cell for every pane, and fixed-height splits such as a row of buttons no longer respond to keyboard resizing.

### Completion menus stay open when nothing matches <JumpToc/> <PrBy :pr="19129" user="kronberger-droid" />

An open completion menu no longer closes when the typed text stops matching.
It shows `NO RECORDS FOUND` and fills again once the text matches, as it did before 0.116.
Cancelling an `@interactive` picker with Esc now closes its menu right away, and Tab on the same line opens the picker again.

### Startup time now starts inside Nushell and is available throughout startup <JumpToc/> <PrBy :pr="19136" user="fdncred" />

`$nu.startup-time` is now measured from the start of Nushell's `main` function, rather than from when the operating system created the process. It no longer includes the time spent loading the executable and its libraries, and `exec nu` starts a fresh measurement instead of carrying over the previous program's time. This applies across platforms.

Before startup finishes, `$nu.startup-time` now contains the elapsed startup time instead of `-1ns`. It is available in config files, `-e` commands, and the `--mcp`, `--lsp`, `--dap`, and `--ide-check` modes. The `--ide-hover`, `--ide-complete`, `--ide-goto-def`, and `--ide-ast` modes can now also access `$nu`, enabling type information for constants built from it and completion of `$nu` fields. Config files loaded with `nu --mcp` now see `$nu.is-mcp` as `true`.

With `--log-level perf`, the "before main" line is gone. The final REPL startup line is labeled "startup (main to first prompt)", and the `--mcp` and `--lsp` startup lines no longer include the time spent serving the rest of the session.

### Other fixes <JumpToc/>

- Fixed some incorrect cell path parsing. ([#19112](https://github.com/nushell/nushell/pull/19112))
- Fixed a regression since 0.115 where custom completers on a `def --wrapped` rest parameter were not called for arguments starting with `-`, so `what --<Tab>` only offered declared flags. ([#19130](https://github.com/nushell/nushell/pull/19130))

## Other changes

### Changed `tui` records <JumpToc/> <PrBy :pr="19102" user="fdncred" />

For scripts that inspect TUI values, a titled widget now has a `title` field in its `widgets` record, and a top-bar label's `slot` is now `titlebar` instead of `title`. When nothing is being previewed, `values.<preview id>.title` is now an empty string rather than `preview`.
